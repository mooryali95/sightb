

## التحقق والتأكيد

### الصلاحيات — الوضع الحالي

بعد فحص شامل للكود وقاعدة البيانات، النتائج كالتالي:

**1. حذف الشركات للأدمن — يعمل بشكل صحيح:**
- سياسة RLS: `has_role(auth.uid(), 'admin')` على `DELETE` للشركات والمشاريع والمحافظ
- واجهة المستخدم: أزرار الحذف والأرشفة محمية بـ `{isAdmin && ...}` في Dashboard و CompanyDetail
- الحذف المتتالي (CASCADE): حذف شركة يحذف تلقائياً المحافظ والمشاريع والعهد والتكاليف غير المباشرة، وحذف المشروع يحذف الموازنة والمصروفات والإيرادات والموارد والمراحل وأوامر التغيير والمخاطر

**2. ارتباط الصلاحيات بالنطاق — يعمل بشكل صحيح:**
- دالة `can_edit` تتحقق من أن المستخدم لديه صلاحية على النطاق المحدد (شركة/مشروع) وليس صلاحية عامة
- دالة `has_access` تتحقق بنفس المنطق للقراءة
- المحرر على شركة "أ" لا يستطيع تعديل بيانات شركة "ب"

**3. إنشاء الشركات — مقتصر على الأدمن فقط** عبر RLS وواجهة المستخدم

### لا توجد تغييرات مطلوبة

النظام يعمل كما هو مطلوب:
- الحذف (شركات/مشاريع/محافظ) = أدمن فقط
- التعديل = أدمن + محرر (على النطاق المحدد فقط)
- الإنشاء = أدمن للشركات، محرر+ للمشاريع والمحافظ (ضمن نطاقه)
- القراءة = أي مستخدم لديه وصول للنطاق

لا حاجة لأي migration أو تعديل كود إضافي. النظام مؤمّن على مستوى قاعدة البيانات (RLS) والواجهة معاً.
